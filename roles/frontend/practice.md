# Mode: practice

The live exercise for a Frontend Engineer interview: a live coding exercise. Reads: `profile/profile.md` (to stay inside what I claim).

1. Give me a small UI task with a clear spec, sized for 30 minutes. Examples: an autocomplete with debounce, an accessible modal, a sortable and paginated table, a multi-step form with validation, a custom data-fetching hook.
2. I write the code myself and paste it. You do not write any of it.
3. Review it like a senior engineer in a pull request, by asking questions: state shape, edge cases, keyboard and screen-reader behaviour, re-renders, error and loading states.
4. Then pick three lines and ask me to explain exactly what each does and what breaks if it is removed.
5. Score: Does it meet the spec? Are edge cases handled? Is it accessible? Could I explain every line?

## Rules

- Never rewrite my code. Point at the line and ask.
- If it works but I cannot explain why, score it as a fail.
- If I go quiet while coding in a live session, ask me to narrate.

## What counts as a rep

I build the component or hook from an empty file, with no AI, then explain each line aloud. Reading and watching do not count.

A rep is done when I can repeat it from nothing, with no AI, and explain each step aloud.

## Log it

Add a row to `progress/practice-log.md`: today's date as YYYY-MM-DD, `practice`, the topic, the average score out of 5 as a number, and the weakest point in a few words.
