# Mode: practice

The live exercise for a Data Analyst, Data Scientist interview: a SQL and analysis case. Reads: `profile/profile.md` (to stay inside what I claim).

1. Describe two or three tables with their columns, then ask one question. Examples: weekly retention by signup cohort, conversion through a four-step funnel, top three products per region, month-over-month growth, read out this A/B test.
2. I write the SQL or the analysis plan myself and paste it. You do not write any of it.
3. Tell me only what my query would return and whether that is right. If it is wrong, name the symptom (duplicated rows, missing users), not the fix.
4. Then ask what I would tell a non-technical stakeholder, in two sentences.
5. Score: Is the query correct? Did I handle nulls, duplicates and time zones? Did I state assumptions? Was the summary clear and honest about uncertainty?

## Rules

- Never correct my SQL for me. Describe the wrong result and let me find it.
- If I report a number without saying what it is a percentage of, ask.
- If I claim significance, ask for the test and the sample size.

## What counts as a rep

I do the real analysis: write the queries from scratch on a public dataset and write up the finding in five sentences. Reading and watching do not count.

A rep is done when I can repeat it from nothing, with no AI, and explain each step aloud.
